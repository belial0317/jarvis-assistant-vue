# 模型路由

组件的模型体系分三层，各司其职。

## 三层架构

```
会话下拉（用户视角）
    ↓ modelId（模型名 或 目录 ID）
后端 ModelRouteResolver（路由决策）
    ↓ 模型名（如 glm-5.2）
LLM 网关（openai-compatible）
```

## 解析规则

后端 `ModelRouteResolver` 按 modelId 的形态决定路由：

| modelId 形态 | 路由行为 |
|---|---|
| 纯数字（如 `2093921362444398593`）| 供应商模型目录 ID → 查出模型名 |
| 非数字（如 `glm-5.2`）| **原始名直传**（网关按名路由） |
| 空 | 回落会话持久化模型 → 仍空回落服务端配置模型 |

## 多模型 + 默认模型（控制台系统参数）

```
系统参数 → 模型关联（勾选目录中的模型）→ 保存
    ↓
组件 config.models = ['glm-5.2', 'deepseek-v4-flash']
    ↓
会话下拉显示这些模型，默认选中 defaultModel
```

用户切换下拉后，后续消息以新 modelId 发送——同一会话内可随时切换模型。

## 供应商模型目录（管理端）

在「供应商管理」页面维护：

- 供应商（名称 / Base URL / API Key / 启停）
- 模型目录（模型名 = 发给上游的 `model` 参数 / 显示名 / 设默认）

系统参数的「模型关联」从目录中勾选——所见即所配，不会出现目录外的模型。

## 会话模型持久化

切换下拉时组件调用 `POST /chat/sessions/{id}` 保存 `modelId`；下次发消息未携带 modelId 时，后端自动回落会话持久化值（兼容旧客户端）。
